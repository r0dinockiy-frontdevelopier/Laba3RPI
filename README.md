# Учебная платформа — лабораторная №3, вариант 12

React-приложение с каталогом лекторов, их дисциплинами, тарифами и достижениями.
Вариант 12 добавляет кастомный хук `useDebounce` и поиск лекторов с задержкой 300 мс.

## Что добавлено

- `src/hooks/useDebounce.js` — переиспользуемый хук на `useState` и `useEffect`.
  Принимает значение и задержку в миллисекундах, возвращает отложенное значение.
- `src/components/LecturerSearch/` — поле поиска по ФИО, список результатов и сообщение об отсутствии совпадений.
- Ввод в поле обновляется сразу, фильтрация запускается после паузы 300 мс.
  Каждый новый ввод отменяет предыдущий таймер.
- `useMemo` сохраняет результат фильтрации между изменениями исходного текста.
- Поиск ищет подстроку в полном ФИО, не учитывает регистр и пробелы по краям запроса. Пустой запрос возвращает всех лекторов после той же задержки.
- Существующее открытие профиля лектора и кнопка возврата сохранены.
- Добавлены 7 автоматических тестов, в том числе проверка количества вызовов фильтрации.

В исходной версии поля поиска не было, поэтому оно добавлено в существующий раздел «Наши лекторы».
Остальное оформление и данные проекта сохранены.

## Установка и запуск

Все команды выполняются из корня репозитория:

```bash
npm ci
npm run dev -- --host 127.0.0.1 --port 5176 --strictPort
```

Открыть http://127.0.0.1:5176. Перейти к разделу «Наши лекторы».
Порт 5176 выбран, чтобы приложение не конфликтовало с предыдущими лабораторными.
Остановка — **Ctrl+C** в терминале с сервером. Закрытие браузера сервер не останавливает.
При повторном запуске достаточно команды `npm run dev ...`, переустанавливать зависимости не нужно.

Если порт занят, остановите прежний сервер в его терминале или укажите другой порт.
Облачным изображениям лекторов нужен доступ к интернету; фильтрация выполняется локально.

## Проверки и сборка

```bash
npm test
npm run lint
npm run build
```

`npm test` выполняет тесты один раз, `npm run test:watch` запускает их в режиме наблюдения.
Проверяются: начальное значение хука, задержка 300 мс, сброс таймера при новом вводе,
изменение задержки, cleanup в Strict Mode и при размонтировании, число фильтраций,
пустой результат, очистка поиска и выбор лектора.
В тестах используются управляемые таймеры, поэтому ждать реальных 300 мс не нужно.

Готовая сборка находится в `dist/`. Проверить её локально:

```bash
npm run preview -- --host 127.0.0.1 --port 4176 --strictPort
```

Открыть http://127.0.0.1:4176. Остановка — Ctrl+C.

## Где лежат данные и маршрутизация

Все данные лекторов хранятся в `src/data/lecturersData.js`.
Фото загружаются по ссылкам Yandex Cloud из этого файла; партнёрские логотипы — из `src/assets/`.
API для поиска не требуется: фильтруется локальный массив по полю `name`.

Отдельного роутера нет. В `src/App.jsx` состояние `selectedLecturer` определяет экран:
`null` показывает главную со списком, выбранный объект — профиль и блоки дисциплин, тарифов и достижений.
Возврат сбрасывает выбор в `null`. Адрес браузера при открытии профиля не меняется.
Пункты шапки используют якорные ссылки на разделы главной страницы.

## Как работает useDebounce

```jsx
const [query, setQuery] = useState("");
const debouncedQuery = useDebounce(query, 300);
```

Поле использует `query`. Фильтрация зависит от `debouncedQuery`.
При изменении значения или задержки эффект запускает `setTimeout`.
Cleanup вызывает `clearTimeout`, поэтому незавершённый таймер отменяется при следующем вводе
и при удалении компонента. Начальное значение возвращается сразу.

Это debounce: отсчёт начинается заново после каждого символа. При непрерывном вводе промежуточные запросы не фильтруют список.
Если пользователь делает паузу больше 300 мс, список обновляется после каждой такой паузы.
В режиме разработки React StrictMode может повторно вызывать вычисления для проверки чистоты;
это не означает появления дополнительного независимого таймера. Одна фильтрация после серии ввода проверена отдельным тестом вне StrictMode.

## Что показать на защите

1. Открыть раздел «Наши лекторы», показать новый поиск и полный список.
2. Быстро набрать «Петров Дмитрий»: текст появляется сразу, после паузы остаётся нужная карточка.
3. Набрать заведомо отсутствующее имя — появляется сообщение об отсутствии результатов.
4. Очистить поиск — через 300 мс возвращаются все карточки.
5. Открыть профиль лектора и вернуться к списку.
6. Показать `useDebounce.js`: два аргумента, `useState`, `useEffect`, таймер и cleanup.
7. Показать тест единственного вызова `filter` и выполнить `npm test`.
8. Открыть ветку `feature/use-debounce-lecturer-search`, коммиты и Pull Request в исходный проект.

Текст для краткого объяснения:

> Добавлен кастомный хук useDebounce. Он получает значение и задержку, хранит отложенное значение в useState
> и обновляет его таймером из useEffect. Cleanup отменяет предыдущий таймер. В поиске используется задержка 300 мс:
> символы видны сразу, а список фильтруется после окончания ввода. useMemo предотвращает повторную фильтрацию
